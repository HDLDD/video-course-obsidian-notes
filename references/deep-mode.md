# 深度模式（视频只当骨架，笔记要比视频深得多）

普通模式的目标是**忠实**：视频讲了什么就记什么，看不清标「待核对」。
深度模式的目标是**机制**：用户会明说「深度要比视频讲的多得多」「基于视频的基础上再展开」——这时视频只是第一层，交付物必须能回答"为什么是这样、代价是什么、错了怎么查"。

## 三层结构（文件名要兼容校验器）

```
<讲号>-<题名>/
  01-视频讲解.md     忠实层：转写精华 + 幻灯片帧 + 逐字照录代码，标时间点与归属
  02-内核深读.md     机理层：结构体逐字段 / 函数逐段 / 宏展开 / 设计取舍
  03-工程与坑.md     应用层：症状 → 机理 → 怎么查（每条机理回指源码）
  00-本讲索引.md     本讲口径汇总 + 「视频口径 vs 源码实际」对照 + 待核对清单
  99-扩展笔记.md     完整可运行示例 + 自测题（标「自拟」）
  assets/            只放视频帧；源码用代码块 + 行号引用，不要截 IDE
```

`verify_course.py` 只认 `00-本讲索引.md`、`99-扩展笔记.md` 和非 `00-` 前缀的正文，所以上面这套不用改脚本。

## 权威来源的次序

1. **本机真实源码**（最硬）。开课前先盘点：内核/框架/SDK 往往已经躺在开发环境里（如 ESP-IDF 自带 `FreeRTOS-Kernel` 与 `-SMP` 两份、上游仓库用 `gh-proxy.com` 浅克隆补齐 Cortex-M 的 port）。
2. 官方文档/标准原文。
3. **课程作者自己的文档站不算证据**——它与视频同源，只能佐证"口径"，不能佐证"实现"。

多棵源码树版本不同时必须逐处标版本（V10.5.1 / V11.1.0 混着说会误导），并说明视频实际用的是哪一代（常出现在画面右下角或工程 `Versions` 栏）。

## 引用纪律：每条结论给 `文件:行号`

- 写之前 `grep -n` 定位、`sed -n '<行>p'` 打开确认，**不许凭记忆**写 API 原型、字段名、默认值。
- 收尾跑 `scripts/audit_citations.py --vault <库> --root <源码树> --root <另一棵树>`：它检查行号是否越界、文件是否存在；本机没有的文件（如 ST HAL、CubeMX 生成代码）**允许引用但必须在上下文写明是"画面 mm:ss 读到的行号"**，否则计入 `unresolved`。
- 体检只保证"这行存在"，不保证"这行支撑该结论"——语义核对交给复核代理。

## 事实分四级，写的时候就要分级

| 级别 | 例 | 写法 |
|---|---|---|
| 源码事实 | `sizeof(List_t)`、分支条件、宏展开 | 直接陈述 + `文件:行号` |
| **推导** | 56 格 ≈1120 B、`portMAX_DELAY`≈49.7 天、115200≈87 µs/字节 | 必须写「**推导，非实测**」并给算式 |
| 画面现象 | 串口打印、调试器状态 | 归给视频，标「视频 mm:ss」 |
| 编译器行为 | `sizeof(enum)` 默认宽度 | **用目标编译器真编译**（静态断言），别拿主机 gcc 推断交叉工具链——这条在本课真翻过车：笔记断言"GCC 默认 4 字节、讲师说 16 位是错的"，`arm-none-eabi-gcc -mcpu=cortex-m3` 实测默认是 1 字节，**讲师是对的** |

能编译就编译（ESP-IDF 用 `idf55-env.cmd`，别在 Git Bash 跑 `export.bat`），写了「本机 `idf.py build` 通过（日期）」就是事实；但**编译通过 ≠ 跑对**，没上板就永远不许出现"实测输出/运行结果"。

## 编排：一代理一讲，复核与订正分开

- **深度模式的工作量是忠实模式的好几倍**：实测 3 讲/代理会撞 150 轮上限（两个代理都在收尾前被打断，其中一个已写完、一个只写完一半）。改成**一个代理一讲**后，10 讲全部一次过。
- 任务书里给「待查证的问题清单」而**不是结论清单**；给源码树路径与版本，让它自己去查。
- 正文写完后两道工序，缺一不可：
  1. **章索引代理兼复核代理**：回填主线/速查表/易错点，同时把各讲的「视频口径 vs 源码实际」判定**逐条 `sed` 开原文重验**，判成立/不成立/证据不足，写进章索引新增的 `## 判定复核` 一节。它只报告正文错误，不改别人的文件。
  2. **订正代理**：拿着汇总清单统一改，且**允许推翻复核代理自己**（本次 18 处订正里有 3 处是复核代理记错行号或张冠李戴寄存器名）。
- 最后再跑一次 `audit_citations.py` + `verify_course.py --strict`，两个都干净才算交付。

## 本课实测数字（可作为体量参照）

10 集 / 2:06:55 的视频 → 54 篇笔记、30 篇正文、90 张帧图、**4156 条源码引用**（全部体检通过）、201 处「待核对」；三轮复核推翻并订正正文错误 18 处，其中 2 处是"笔记把讲师判错了"。

## 证据链要能脱离素材生存（三个脚本）

笔记里的「视频 03:35」是给**人**看的；素材清理以后，没人能回到那一秒，截图台账也没了。三个脚本把这件事变成可验证的：

| 脚本 | 解决什么 | 落在哪 |
|---|---|---|
| `add_time_links.py` | 纯文本时间戳 → 可点跳转（`?p=N&t=SS` / 合集用 `?t=SS`）；vault 有 Media Extended 时自动加 `#t=MM:SS` 变成 Obsidian 内可点播放 | 原位替换，幂等，**跳过围栏代码块** |
| `build_frame_ledger.py` | 截图 ↔ sha256 ↔ 时间点 ↔ 源帧；媒体删了也能证明图没被换、出自第几秒 | 每讲根目录 `frames.json`；`--check` 查漂移 |
| `check_code_ocr.py` | 本地 OCR 读帧，把代码块**锚定到它引用的那一帧**再比骨架串，只报"同行不同字"；已滤掉行号栏与 IDE 参数名提示 | 报告写工作目录，不进 vault |

三条实践细节：

- **把它当筛子、不当判据**：在 C 与 FreeRTOS 两库共 21 条候选里，逐条对照帧后**没有一条是笔记错误**——全是 OCR 噪声（`GPIO`→`GPI0`、`On`→`0n`、光标 `↓`、行号栏、IDE 的 `Size:`/`Timeout:` 提示）。它能帮你把 500 多行代码缩到 20 条去看，但最终判断必须回到帧。

- **链接绝不进代码块**：URL 里的 `//` 会让 `verify_course` 的注释剥离提前截断，一个 `/* */` 里的链接能把整块括号配平弄坏；脚本必须跟踪围栏状态，误插了用同样规则回滚。
- **OCR 只查"照录"**：`02/03/99` 里的代码是作者补的，天然不可能出现在画面上；带「笔记补充 / 未经编译验证 / 自拟」的代码块一律跳过，否则满屏假阳性（实测：不过滤时 15-3 立刻报一条，过滤后 0）。
- **台账放讲根目录而不是 `assets/`**：`assets` 的计数就是"截图数"，塞 JSON 进去会把课程索引的"385 张截图"变成 385+讲数。脚本只数图片扩展名，台账另放。
